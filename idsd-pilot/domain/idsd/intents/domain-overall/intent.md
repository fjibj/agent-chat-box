# 意图：域层（Domain）总体意图 —— 声誉驱动的多群联盟层

## 目标

为多个群提供一个声誉驱动的联盟层：群加入域后声明自己的能力，其他群可以通过域发现这些能力并发起跨群协作，使跨群协作从手动对接变成自动匹配，且全程不暴露群内部细节。这是「团队 → 群 → 域 → 世界」四层结构的第三层，向上为"世界"层保留递归扩展的可能。

## 约束

- **分形递归（规则预算 ≤ 1）**：域层只能复用团队/群层已有原语——统一信封、契约、标签匹配、信誉、授权闸门——只允许新增一条规则：信誉聚合。任何新功能必须能用现有原语的组合表达；需要新增规则族时必须停下来由产品所有者人工决策。
- **只处理群级事务**：域只负责群级别的注册、能力声明、信誉聚合与任务路由；不直接调度群内的 Agent、不介入群内通信、不持有群内数据。
- **递归复用联邦协议**：群 Hub 作为 Runner 连接域 Hub（Hub of Hubs），复用现有 Hub/Runner/poll/信封机制，不发明新协议。
- **向后兼容**：不启用域功能时，现有团队/群行为完全不变；schema 迁移 v9→v10 不破坏现有数据。
- **数据边界**：域只持有群级元数据（成员、能力声明、聚合信誉、任务索引），不持有群内任务内容、消息、Agent 细节。
- **信誉聚合单一且可解释**：域级信誉是群在各成员群信誉的单一聚合函数的结果，不引入多因子加权模型。
- **能力语义与群层一致**：群向域声明的能力沿用群层标签语义（`required_labels ⊆ 能力标签`），发现结果以域级信誉为主序。
- **成员机制同构**：域的创建、邀请、退出复用群的机制——发起群成为域主，其他群通过邀请码加入。
- **不做市场机制**：定价、竞价、结算不属于域层 v1，任何此类需求推迟到 World 层或另行决策。

## 失败条件

- 任何域层功能需要读取群内部数据（群内消息、Agent 通信、内部任务日志）才能工作。
- 域层规则族数量超过群层规则族数量 + 1（即新增了除信誉聚合以外的规则族）。
- 不启用域功能时，现有团队/群功能行为发生变化。
- 群退出域或能力下线后，超过 60 秒仍出现在发现结果中。
- 单个群可通过操纵信誉垄断域级排序（如无限刷分）。
- 域 Hub 故障导致成员群内部功能不可用。
- 域层引入新的基础设施（数据库引擎、消息中间件、新 npm 依赖）。
- 域级能力发现暴露查询方的意图或群内敏感信息。
