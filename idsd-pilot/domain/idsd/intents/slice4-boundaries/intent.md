# 意图：切片 4 —— 多域交互的边界处理

## 目标

加固域层的边界完整性：域与群、域与域之间的数据与行为边界。域解散、群退出、群删除时，域层数据（成员关系、协作任务索引）必须清理干净，不留孤儿记录；域级信誉按域独立，评分与数据不跨域泄漏。**本切片以清理与隔离为主，不新增机制。**

## 约束

- **解散域**：删除该域全部 `domain_tasks`（连同现有 domain_members、domains 清理）。
- **群退出域**：删除该群作为 requester 或 target 的 `domain_tasks`（协作索引随成员关系消失）。
- **群被删除**：清理该群在所有域的 `domain_members`；清理 requester 或 target 为该群的 `domain_tasks`；若该群是某域 owner，该域一并解散（连同其 domain_tasks）——域依赖其 owner 群存在。
- **评分边界**：协作任务索引已随退出/解散/删群清理 → 评分接口返回 404（任务不在本域）。评分对象离开域后不可再评。
- **信誉隔离**：域级信誉按域独立聚合。域协作全生命周期事件（任务完成/失败、协作评分）携带所属域标记（`reputation_records.domain_id`）；聚合与连续拒绝计数只计入 `domain_id IS NULL OR domain_id = 当前域` 的记录。群层事件（无标记）计入所有域。
- **跨域不可见**：所有域 API（能力列表、发现、信誉、协作任务、评分）均按域成员校验；域 A 成员不可见域 B 的数据，非成员一律 403。
- **向后兼容**：不新增 npm 依赖；现有 API 行为不变（除清理语义增强）；schema v11 → v12：`reputation_records` 增加可空 `domain_id` 列（NULL = 群层事件，计入所有域；非 NULL = 域协作事件，只计入该域）。
- **本切片不做**：跨域协作、World 层、市场机制、UI。

## 失败条件

- 解散域 / 群退出 / 群删除后，遗留的 domain_tasks 仍可被操作（评分、查询）。
- 目标群已退出域的协作任务仍可评分成功。
- 群在域 A 的评分事件改变了该群在域 B 的信誉。
- 域 A 的成员或数据对域 B 成员可见。
- 新增规则族或 npm 依赖。
- 任何现有测试失败。
