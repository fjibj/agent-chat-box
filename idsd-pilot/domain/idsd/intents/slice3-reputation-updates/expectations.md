# 期望：切片 3 —— 信誉更新机制与异常检测

## 成功场景

| 场景 | 期望行为 |
|---|---|
| 域协作发起 | 群 A 发起协作（要求 data-analysis 能力），域路由到唯一匹配的群 B，任务出现在群 B 的群任务列表中，状态 pending |
| 协作执行回流信誉 | 群 B 的团队认领 → 授权批准 → 任务完成，群 B 的域级信誉在查询中反映 +1 |
| 评分 approved | 发起群 A 对协作结果评分 approved，群 B 的域级信誉再 +1（累计 +2） |
| 协作任务列表 | 域成员可查询本域协作任务（含发起群、目标群、状态） |

## 失败场景

| 场景 | 期望行为 |
|---|---|
| 无匹配群 | 发起协作要求的能力无人声明 → 400 |
| 非成员发起 | 非成员群调用发起协作 → 403 |
| 非发起群评分 | 域内其他群（非发起群）评分 → 403 |
| 未完成评分 | 任务未完成时评分 → 400 |
| 重复评分 | 同一任务评分两次 → 400，第二次不生效 |

## 边界场景

| 场景 | 期望行为 |
|---|---|
| 路由排除自身 | 域内唯一具备所需能力的群就是发起群自身 → 无匹配 → 400 |
| 连续 5 次拒绝标记 | 群 B 连续 5 次协作被评 rejected → discover 结果中 B 的 flagged = true |
| 单次拒绝不标记 | 仅 1 次 rejected → flagged = false |
| approved 打断连续 | 3 次 rejected + 1 次 approved + 1 次 rejected → 连续计数被打断 → flagged = false |
| 评分后信誉可查 | 评分事件写入后，域信誉查询立即反映新值 |
