# 意图：切片 2 —— 能力发现与信誉查询

## 目标

让域内的群能声明自己的能力，并让成员群通过"能力发现"找到匹配的协作对象：按能力子集匹配，结果按域级信誉降序返回。域级信誉是群在域内各成员群中信誉的单一聚合。**本切片只做查询（读）**：能力声明的写入、发现的匹配排序、信誉的聚合查询；信誉的更新机制（评分事件）与异常检测属切片 3。

## 约束

- **能力声明**：capabilities 是字符串数组，存于 `domain_members.capabilities`（切片 1 已建字段）；成员群可更新自己的声明。
- **子集匹配**：沿用群层标签语义——`required_capabilities ⊆ 声明能力` 即匹配（复用 federation LabelMatcher 思路，空 required 匹配所有成员）。
- **域级信誉**：单一聚合函数——群内各团队在"域内成员群"中的信誉分之和的聚合（如均值）；不引入多因子加权模型；无任何记录时信誉 = 0。
- **发现结果**：返回匹配群的 `{group_id, group_name, capabilities, reputation}`，按信誉降序；信誉相同按加入时间升序稳定排序。
- **访问控制**：声明能力 / 发现 / 信誉查询仅限域成员；非成员 → 403。
- **退出即消失**：群退出域后，其能力与信誉不再出现在该域的查询结果中。
- **向后兼容**：不新增依赖；现有 API 不变；TypeScript strict + ESM；注释英文。
- **本切片不做**：信誉更新事件（切片 3）、异常检测、跨域任务、域 UI。

## 失败条件

- 非成员群能声明能力、调用发现或信誉查询。
- 发现接口返回 `required ⊄ 声明能力` 的群。
- 信誉计算引入多因子加权模型（违背"单一聚合函数"约束）。
- 信誉查询返回非数值或缺失字段。
- 任何现有测试失败；新增 npm 依赖。
