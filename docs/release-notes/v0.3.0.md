# Agent Chat Box v0.3.0 — 域层（Domain）落地 + 工程链路收口

**发布日期**：2026-09-06 · **标签**：`v0.3.0` · **提交**：`d5c9e0f`

## TL;DR

- 新增第三层「**域（Domain）**」：把若干群登记成一个域，域内声明能力、按能力发现伙伴群、跨群自动派单协作，并让信誉**按域隔离**。
- 新增 **`Domains` 页面**（`/domains`）：建域 / 邀请码加入 / `Capabilities` 声明 / `Discover` 发现 / `Collaboration Tasks` 派单与评分 / `Reputation` 信誉看板。
- **建群即建群聊频道**（关闭人工验证最后一个缺口 GAP-19）。
- 修掉一批被遮蔽已久的工程问题：web 端 tsc 错误、Tailwind 相对路径、Playwright harness 端口错配、CI 双份 React。**GitHub Actions 自 2026-05-17 起首次两个 job 全绿。**
- 本版同时是 v0.2.0 之后所有未打标签工作（`0.2.0-followup`、`0.2.0-followup-patch`、GAP-19）的**首次发版**。

## 为什么需要「域」这一层

Group 层解决的是「两个团队在同一个群里怎么协作、要不要授权」。当同一批团队同时出现在多个项目里，光有群就不够了：

1. **谁能干这件事**不该靠记忆 —— 域内每个群声明能力，`discover` 用 `required ⊆ declared` 子集匹配并按信誉排序。
2. **活该派给谁**不该手工挑 —— 发起域协作任务时自动路由到能力匹配的群。
3. **信誉不能串味** —— 群层事件计入所有域（`domain_id IS NULL`），域协作事件只计入该域（`domain_id` 非空）；连续 5 次 rejected 标 `flagged`，一次 approve 打断连击。

规则预算：域层全程只新增「信誉按域聚合」这一条规则族，路由 / 授权 / 评分 / review 语义全部复用群层原语。

## 新功能一览（域层，14 个端点）

| 能力 | 页面入口 | 服务端点 |
| --- | --- | --- |
| 建域 / 列域 / 域详情 / 解散 | `Create Domain` 表单 · 域列表卡片 | `POST/GET /api/domains`、`GET/DELETE /api/domains/:id` |
| 邀请码 / 加入 / 退出 | 域详情 `Members` 区 | `POST /api/domains/:id/invite`、`POST /api/domains/join`、`POST /api/domains/:id/leave` |
| 能力声明与查询 | 域详情 `Capabilities` 区 | `POST/GET /api/domains/:id/capabilities` |
| 按能力发现伙伴群 | 域详情 `Discover` 区 | `GET /api/domains/:id/discover` |
| 域协作任务与评分 | 域详情 `Collaboration Tasks` 区 | `POST/GET /api/domains/:id/tasks`、`POST /api/domains/:id/tasks/:tid/rating` |
| 域级信誉看板 | 域详情 `Reputation` 区 | `GET /api/domains/:id/reputation` |

行为约束：owner 群禁止退出；邀请码可限次数与有效期；重复入群拒绝；解散域 / 退出域 / 删群均级联清理 `domain_tasks` 与 `domain_members`。

## 数据库变更

schema **v9 → v12**：`domains`、`domain_members`、`domain_tasks` 三张新表 + `reputation_records.domain_id` 列。
启动时按 `PRAGMA user_version` 自动逐段迁移，**无需手工操作，已有数据保留**。

## GAP-19：建群即建群聊频道

`POST /api/groups` 现在自动创建同名聊天频道并把 owner 拉入；删群级联清理频道；频道创建失败不会残留半态群；联邦 `join` 不自动加频道。
这是人工验证 A~M 里最后一个开放缺口，也是本项目第一次用 IDSD 流程交付的修复（8 个 holdout 场景全过）。

## 工程与质量（这一版顺带修掉的）

- **web 类型检查** — 补 `vite-env.d.ts`、导出 `TaskCardProps`、修 `TaskDetailModal` 测试夹具；根 `typecheck` 现在真的覆盖 `packages/web`（此前被 `exclude` 掉，所以 5 个 tsc 错误长期无人看见）
- **Tailwind 路径** — `content` 改 `path.resolve(__dirname, ...)`，任意目录构建产物一致（此前从 `packages/web` 构建只有 4.89 kB、丢掉全部工具类）
- **E2E harness** — 收拢为根目录单一 Playwright 配置（拉起 server 并服务已构建 UI）。`e2e-test` job 此前连续 13 次失败，根因是 `baseURL :3000` 配 `webServer` 起 vite `:5173`，永远等不到服务
- **双份 React** — `packages/web` 自带完整工具链（react / react-router-dom / vitest / testing-library / jsdom / typescript / coverage），`vitest` 的 `react` 别名改指本包，干净依赖树下不再 `Invalid hook call`
- **CI** — `unit-test` 现在跑 typecheck + lint + 455 用例 + coverage + `quality:gates`；两个 job 均执行三处 `npm ci`（root / packages/web / packages/server）
- **仓库卫生** — `e2e/.auth/`（登录态）与 `packages/web/.env.development` 移出跟踪，新增 `packages/web/.env.example`

## 快速上手

```bash
git clone https://github.com/fjibj/agent-chat-box.git
cd agent-chat-box

# 三个 lockfile 都要装（尚未切 npm workspaces）
npm ci && npm ci --prefix packages/web && npm ci --prefix packages/server

npm run build          # shared + server + daemon + web
npm run dev:server     # :3000，同时用 @fastify/static 服务 packages/web/dist
npm run dev:web        # :5173，/api 与 /ws 代理到 :3000

# 需要跨机执行时再起 Daemon
node packages/daemon/dist/daemon.cjs --server ws://localhost:3000 --token <machine-token>
```

自检一把：

```bash
npm run typecheck      # packages/*/src + packages/web
npm test               # 455 用例
npm run quality:gates  # TODO 基线 / 孤儿组件 / 硬编码版本
npm run test:e2e       # Playwright（默认 msedge，CI 用 chromium）
```
